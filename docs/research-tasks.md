# 調査タスクリスト（Sonnet 実行用）

**背景**: 電話 × OpenAI Realtime API（ChatGPT Live）で「給湯器修理窓口サポート」のデモを作る。
用途は個人の実験・ポートフォリオ。電話番号は国不問。実装は Twilio Media Streams ↔ 自前WebSocketブリッジ ↔ OpenAI Realtime API を第一候補としている。

**共通ルール（全タスク共通）**
- 一次情報（公式ドキュメント、公式ブログ、公式料金ページ）を優先。個人ブログは一次情報の裏取りが取れる場合のみ使う。
- **必ず出典URLと、そのページの最終更新日または確認日を併記すること。**
- 情報が古い/見つからない場合は「不明」と明記する。推測で埋めない。
- 出力は各タスクごとに「結論(2〜3行) → 根拠 → 出典」の順。

**優先度**: P0 = これが分からないと着手できない / P1 = 設計判断に効く / P2 = あると良い

## P0-1. Twilio の US ローカル番号の取得条件とリードタイム
- 日本在住の個人アカウントで US ローカル番号（+1）を取得できるか。本人確認・住所証明（Regulatory Bundle / Address要件）は必要か。
- 取得から利用開始までの実際のリードタイム（即日か）。
- 月額と、日本の携帯からの着信・日本の携帯への発信の従量単価。
- Toll-Free番号との違い（Toll-Freeは検証審査が必要か）。
- **判断基準**: 「日本在住個人が本人確認なしで即日US Local番号を取得し、日本から発信して着信させられるか」に Yes/No で答えること。

## P0-2. Twilio トライアルアカウントの制限と解除条件
- トライアル状態での制限（発信先の verified 制限、通話冒頭のアナウンス挿入、その他）を正確に列挙。
- 有料アカウントに切り替える最低チャージ額と、切り替え後にアナウンスが消えるか。
- 日本からの支払い（クレジットカード）が通るか、既知の問題があるか。
- **判断基準**: デモ品質の通話を成立させるために最低いくら払う必要があるか、金額で答えること。

## P0-3. OpenAI Realtime API の現行仕様（2026年8月時点）
- 現在の推奨モデル名と、音声（voice）の選択肢一覧。
- 電話用音声フォーマット `g711_ulaw` / `g711_alaw`（8kHz）の入出力サポート状況。
- WebSocket接続方式と、SIP直収方式（`sip:{project_id}@sip.api.openai.com` 系）の両方が現在も提供されているか。SIP方式のドキュメントURL。
- 割り込み関連のイベント名（`input_audio_buffer.speech_started` 等）の現行名と、サーバー側VADの設定パラメータ。
- **判断基準**: 電話帯域でそのまま使えるか Yes/No、および SIP直収が「今すぐ試せる正式機能か / ベータか / 廃止されたか」を明示すること。

## P0-4. Realtime API の音声課金と、5分通話1回あたりのコスト試算
- audio input / audio output のトークン単価（テキストと別建てか）。cached input の扱い。

- 利用上限アラート/ハードリミットの設定方法。
- **判断基準**: 「デモを50回テストしたらいくらか」を円で答えること。

## P1-7. 公開URL（トンネル/ホスティング）の選択肢比較

- ngrok 無料枠の現行制限（固定ドメイン可否、セッション時間、同時接続）。
- Fly.io / Render / Railway で WebSocket サーバーを常設する場合の無料〜最安プランと、WebSocketのアイドルタイムアウト制限。
- **判断基準**: 「デモ当日に切れない構成」として最も安全な選択肢を1つ推奨し、理由を述べること。
